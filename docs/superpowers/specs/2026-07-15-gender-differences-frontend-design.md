# 男女命差异前端展示设计

## 目标

让用户在现有报告中直接看见同盘男女在大运方向、交运、小运、六亲映射和神煞权重上的差异，同时保持当前报告的阅读顺序和视觉风格。

## 已选方案

采用“平衡区块”方案。在“当前大运”之后、“流年”之前新增“运势起点与六亲”区块，不增加新页面或页签。

## 区块结构

1. 摘要行
   - 显示性别、大运方向和首步大运。
   - 示例：`女命 · 顺排`、`首步大运：己酉`。
2. 交运信息
   - 使用 `dayun.jiao_yun` 显示上一节或下一节，以及折算后的岁、月、日、时。
   - 保留“三天折一岁，余一天折四个月”的规则说明为悬浮提示或次级文字。
3. 小运序列
   - 使用 `xiaoyun.periods` 展示未交大运前的小运，一岁一柱。
   - 桌面端横向排列，移动端允许横向滚动，不压缩干支文字。
4. 六亲映射
   - 使用 `kinship` 显示配偶星、子女星，以及接口实际返回的姻亲关系。
   - 男命显示妻星，女命显示夫星，不在前端重复推导十神。
5. 神煞权重
   - 使用 `spirit_score` 和 `spirits`。
   - 仅在男命命中孤辰或女命命中寡宿时显示敏感提示；提示为传统命理规则说明，不输出确定性婚姻结论。

## 数据与渲染边界

- 前端只展示后端返回的数据，不重新计算顺逆、交运年龄、六亲十神或神煞分数。
- 新增一个独立构建函数生成区块 HTML，由现有报告构建流程调用。
- 字段缺失时隐藏对应子区域；整个新区块没有可展示数据时不渲染。
- 所有动态文本继续经过现有 `esc()` 转义。
- 现有“原始依据”中的大运列表保留，作为完整规则明细；新区块负责用户可读摘要，不替代原始数据。

## 视觉与交互

- 沿用现有报告区块标题、边框、文字层级和颜色变量，不引入新的主题体系。
- 摘要采用两列信息行，小运采用紧凑标签序列，六亲采用无嵌套卡片的数据行。
- 神煞提示使用低饱和警示色和左侧细边，不使用强烈红色警报。
- 新区块加入现有报告导航，标签为“运势起点”。
- 深色模式使用现有 CSS 变量，不写固定浅色背景。

## 验证

- 前端单元测试覆盖男命和女命字段、缺失字段降级、动态文本转义。
- 浏览器验证桌面和移动端，检查小运滚动、文字不溢出、深浅色模式和导航定位。
- 使用同一出生时间分别生成男女报告，确认方向、首步大运、小运、配偶星和神煞提示不同。
- 完成后运行完整后端测试、前端测试和浏览器烟雾检查。

## 非目标

- 不重做整套报告视觉。
- 不新增男女命对比工具或双栏对照模式。
- 不在前端复制排盘算法。
- 不扩展新的命理规则或调整校准阈值。
