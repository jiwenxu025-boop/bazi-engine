# 校准与锁定验证规范

## 目的

校准数据用于发现规则回归和记录已验证信号，不用于宣称预测准确率。历史案例集只作为开发回归集；只有在规则冻结后录入、且从未用于调参的案例才能进入锁定验证集。

## 案例集

- `development`：现有案例和调参期间新增的案例。允许用于定位缺陷，不能作为独立效果证据。
- `holdout`：规则冻结后新增，不能因为结果不佳而删除、改写或用于调参。

锁定案例必须具备完整出生年月日时、来源说明、来源可信度、每个事件的方向，以及可选但优先的已核实无事件年份。事件方向使用 `正面`、`负面`、`中性` 或 `未知`；方向未知时不得参与方向一致性统计。

## 评分口径

每次输出必须把以下指标分开报告：

- 同年同类覆盖
- 相邻年份或姐妹类别容差覆盖
- 方向一致率
- 已核实无事件年份的强信号误报
- 各类别样本数和无法判定数

容差结果不能并入严格覆盖，也不能称为准确率。只记录正向事件而没有已核实无事件年份时，不能计算误报率。

## 录入流程

1. 先确认出生时间、事件年份和事件描述，再创建案例。
2. 选择 `development` 或 `holdout`；一旦进入 `holdout`，不得用于阈值或规则调参。
3. 在 `event_details` 中记录方向、来源与必要说明；在 `negative_years` 中仅记录确认为无该类事件的年份。
4. 锁定案例录入后不能通过 `add_case`、`update_events` 或家境上下文接口覆盖；评估报告必须显式选择 `dataset="holdout"`，日常校准报告只统计 `development`。
5. 先运行全量测试和对应类别校准，再只读生成锁定集报告。
6. 规则修改必须新增能复现问题的开发案例；锁定集只用于最终观察，不作为调参依据。
